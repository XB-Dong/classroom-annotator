## 2. 批准后可转交的任务正文

> Windows Leader 正在执行获用户批准的 P0.1，范围是 PostgreSQL 迁移与 Mac 媒体存储。请先阅读 GitHub 指定规格提交中的 `P0.1-PLAN.md`、`specs/p0.1/mac-media.md`、`specs/p0.1/acceptance.md` 和 `docs/waves/P0.1/tasks.md`。使用 Leader 给定的准确 SHA，不自行切到未知最新版。你负责 Mac 媒体执行端及本机运行配置，不负责业务数据库或标注状态。
>
> 首先只读核验已有本地服务的接口版本、监听端口、实际状态、系统架构、Go/FFmpeg版本、授权素材登记、磁盘余量、休眠与启动方式，给Windows返回脱敏能力记录。不要返回密钥、绝对敏感路径、视频内容或公司 API 原始响应。现有服务尚未确认符合桥接v1契约，不能凭推测说已兼容；保留原服务和数据，不直接覆盖。
>
> 在契约已冻结且 Leader 下发路径所有权后，使用同仓库 `backend/cmd/media-agent` Go启动入口，媒体和运行状态在代码目录外。实现登记/流式上传、幂等抽帧、取消/租约、不可变帧清单、媒体Range、完整ZIP与过期ZIP清理。Mac不访问云端PostgreSQL、不管理标注revision、不把媒体送给GLM。先用合成视频测试，再用明确授权的样本联调。
>
> SSH使用专用账号及上表指纹，私钥保持本机；仅反向转发指定云端loopback端口到本地loopback服务。Windows确认新转发服务已配置并通过检查前，隧道继续等待。通过已有可信信息核验并固定known_hosts，不能简单关闭主机检查。不要尝试root登录或开放Mac公网入站。
>
> launchd管理Go媒体Agent和隧道；Token放外部权限受限文件，随机桥接Token不等于演示密码或公司API Key。SSH重连有间隔，进程失败有状态记录；不要写无限coding/修复循环。真实媒体读取要遵守授权素材清单，不枚举整个Mac磁盘。
>
> 每项交接写时间戳、契约/Agent版本、Git提交、实测动作、测试exit、证据索引、阻塞和允许继续的范围。不得把合成结果写成真实联调通过。Windows Leader统一合入/发布；若需要双方共享代码变更，先交接，禁止同时改主分支。

## 3. 双方必须交换的信息

| Mac → Windows | Windows → Mac |
| --- | --- |
| 架构、Agent/契约版本、FFmpeg状态 | 已批准规格SHA与明确任务允许路径 |
| 授权sourceId、样本hash/尺寸/时长、有限素材数 | 云端接入版本、仅私有地址端口的配置确认 |
| Agent可用性、磁盘余量、常态运行/休眠条件 | 经可信连接核验的账号与host fingerprint |
| 合成与真实样本结果分开、错误安全枚举 | 转发/SSH限制/无媒体文件验收结论与范围 |
| 文件manifest与操作状态、有限重试计数 | 桥接Token通过用户授权的私密渠道配置，不发到共享文档 |

如果真实Mac缺席，Windows可先完成数据库和合成端验证，但真实Mac验收写not_run，整体不能completed。无需把整批视频压缩搬到Windows/云端。
