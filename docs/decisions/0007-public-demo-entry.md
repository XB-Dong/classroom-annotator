# 决策 0007：追加密码保护的公网演示入口

日期：2026-10-13。用户在决策0006已许可当前云端真实脱敏素材及简易密码的基础上，进一步要求“公网地址给一个”。此次新增同一演示云主机的公网业务 HTTP 入口，不启动 P1/P2。

选择可选 public Compose overlay：新增公网 HTTP 80，同时保留本机 SSH 转发使用的 loopback 8180。必须与 password overlay 一起部署；页面、API 和媒体仍受既有密码认证，只有无业务数据的 liveness 路径豁免。Grafana、Prometheus 保留 loopback，不新增公网映射。

public frontend 自带同一 Nginx 配置、认证片段和外部凭证的只读挂载，避免遗漏单独 password 参数时丢失认证；认证片段本身仍只有一份，外部凭证路径必须配置。仍以三份显式配置作为当前部署/恢复方式，并验证两文件 base+public 合并也保持认证。未采用跨文件 `extends`：实际检验发现其相对 bind 路径会再次以被继承文件目录解析，造成错误的 `deploy/deploy` 路径；改为少量显式挂载，保持路径可读与可验收。

公网主机地址、实际凭证和媒体保持在仓库外；source 只保存可配置端口和部署方式。外部环境持久选择 base/password/public 三份 Compose 配置。验收须从开发机直连公网确认未认证401、正确认证页面/API200，以及现有监控不被额外发布；仅在云端本机 curl 通过不能宣称公网可访问。

此次仍采用用户已指定的 HTTP Basic 演示门禁，不宣称 HTTPS 或网页表单登录已实现。内置浏览器原生认证流程存在用户报告的兼容问题，当前建议独立 Chrome/Edge 访问。未来更换认证方式需要独立实现和用户实际登录验收。
