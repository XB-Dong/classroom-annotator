# 决策 0004：P0 以本地材料验收，真实环境试验后置

版本：0.6.0｜确认日期：2026-10-13｜状态：用户已确认，产品实现尚未启动

依据：用户要求“计划可以先不管 mac 那边，开发完后生产环境会试验的，先按本地视频等材料为准”。本决定替代决策 0001 第 05 项以及旧的核心/内网双门槛完成规则。现行角色/模型仍以决策 0003 为准，其他已确认选择不变。

## P0 验收范围

- 本地视频上传、抽帧、标注编辑、保存恢复、进度、导出，以已提供材料与合成测试数据验证。
- 公司 API 适配器仍属于 P0，依据交接包实际观察结构实现解析、分页、channel=4 筛选、播放地址获取和视频导入；使用虚构业务值的合成 API/媒体集成验证。不省略适配器，不硬编码响应、路径或实际凭证。
- 移除原 `P0-VID-002B` Mac 内网真实导入验收。保留 `P0-VID-002A` 作为材料驱动适配器集成门槛，避免重编需求 ID。
- 云端完整业务闭环、测试、CI、监控、智谱代码审核/实际浏览器体验、审计和最小运行/恢复说明仍须通过；不因真实联调后置而取消其他门槛。
- 不要求当前 Windows 开发依赖 Mac、内网 GitLab 或公司真实 API 连通。代码搬运安排和真实环境试验留到开发完成后。

## 完成状态与真实证据

全部现行 P0 门槛通过可报告 `status=completed`，报告必须注明验收基于本地/合成材料；门槛未通过报告 `partial`/`blocked`。不再使用旧的 `core_ready_pending_intranet` 作为现行交付状态。

公司 API 实际运行环境未试验时另记 `realApiVerificationStatus=not_run`，不影响 P0 完成。开发完成后真实环境试验记录项目 SHA、环境、授权数据范围、实际导入步骤与脱敏结果；通过或失败按真实事实更新，不能用上游材料、模拟服务或本地上传冒充真实联调。

## 数据与授权边界

现有课堂视频/图片仅按原许可用于 Windows 本地开发检查，不上传 GitHub、个人云或第三方审核模型；云端和智谱演示使用合成或另获明确授权的数据。此次验收调整不扩大原始材料许可，也不授权现在操作敏感生产资源。
