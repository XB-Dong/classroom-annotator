# P1整文档增强使用引导规格

版本：0.1.0｜待审核；用户要求不做向量化，把完整使用文档给API选择回答。

## 1. 固定方案

一个受控Markdown使用手册 `docs/product/ANNOTATOR-GUIDE.zh.md`，有版本/稳定章节ID。每次问答将整份文档作为上下文，Go直接调用可配置GLM HTTP chat completion，模型选相关内容回答并给章节引用。没有文档分块检索、embedding、向量库、搜索服务、用户上传知识库或Agent工具链。

这是document-grounded QA，产品名称“使用指南”；不宣传已经做了向量RAG。Go仍是唯一产品入口；Python仅做人头检测，不承担聊天，也不使用OpenCode作为线上应用服务。

默认模型glm-4.7-flash，API地址/Key文件/模型可配置，可信供应商origin由服务端配置，不接用户提供URL。R0核对公司额度/实际chat接口，失败有明确结果；不擅自改供应商/模型或假装答复来自API。官方文档本次获取未成功，不能以旧研发适配器成功证明新产品接入成功。

## 2. 文档和回答

- 发布手册与页面实际按钮/行为同步，一起构建进Go受控资源；运行时计算SHA-256。初稿描述的是P1待开发流程，发布前必须用实际界面核对，不能把未开发功能写成已上线。
- 手册整体上限32KiB，超过就构建/配置失败，不能悄悄截断到模型看不到关键章节。每次发送整个受控版本，不只发送搜索出来的片段。
- 请求内容仅含system约束、全文、操作问题。单轮回答，不保存数据库聊天历史或附加其他用户对话，不读取工作区素材、标注、身份资料或课节。
- 回答中文、简洁步骤、明确引用至少一个合法sectionId；文档未覆盖回答“当前手册没有说明”，不编造按钮/能力、检测准确率或账号权限。
- 模型返回answer/references结构，Go验证引用存在于当前手册并补可信标题/锚点；非法/缺引用、损坏JSON、超长正文视为HELP_INVALID_RESPONSE。不能把“引用合法”说成内容绝对可靠。
- 只渲染文本/受控章节链接，不执行HTML/脚本、不采用模型生成的任意外链。不接受“忽略规则/泄露系统提示/自动完成复核”等输入来改变服务端行为；问答没有执行标注/SQL/文件读取工具，系统数据不在上下文内。

## 3. 账号、资源和降级

静态手册和注册说明可未登录查看；POST问答必须有有效会话、成员资格、CSRF/Origin，并执行authGeneration隔离迟到响应。问答问题上限1000字符/4KiB，答复上限1500字符，max_tokens初始1024（R0核对实际供应商支持），整请求受15秒总超时。

并发最多2，单用户10次/小时且最多1个在途问题；有限内存计数器足够单机原型，不引入Redis，重启计数重置的边界在说明中记录。不自动重试收费生成，429/超时可由用户手动再问。无Key/连接失败/额度不足显示HELP_UNAVAILABLE并保留全文/章节导航，不能用固定文字冒充模型返回。

供应商Key只挂载到Go、禁止重定向转发认证，不返回浏览器、不记录完整问题/文档/API响应或敏感header。只有有限错误类型、耗时、文档版本等低基数指标。UI提示不要输入密码/公司业务敏感信息；仅解释平台操作，不接受素材附件。

## 4. API与文件边界

| 接口 | 行为 |
| --- | --- |
| GET /api/v1/help/document | 当前安全手册全文、version、SHA、章节列表；无私有业务数据，可匿名 |
| POST /api/v1/help/questions | 登录+CSRF，输入question，返回answer、references[]、documentVersion、documentSHA256；错误有安全code/requestId |

Go新能力 `backend/internal/help/{document,provider,service,http}.go`，Leader协调OpenAPI与配置。Go不能直接embed模块外的 ../../docs：统一verify/build脚本将canonical手册复制到被Git忽略的 `backend/internal/help/resources/ANNOTATOR-GUIDE.zh.md`，再由go:embed编入，构建核对原文/生成副本SHA一致；先生成再Go检查，不手动维护第二份知识文档。前端新增 `features/help/{HelpPanel,DocumentView}`，默认折叠，和复核面板相互切换；不遮挡标注操作。文档维护属于项目内容，不放无关工具或媒体到code。

## 5. 验收

单元/合成供应商契约测试必须检查**完整文档逐字/哈希一致地发出**、问题大小/鉴权/CSRF/限流、无业务数据和Key外泄、非法引用/损坏响应、15秒超时、退出后的迟到结果。使用fake server测请求不代表真实GLM已通过。

真实产品API至少3个问题：如何开始预标注、如何处理版本冲突、高风险框能否批量通过；实际答案引用正确章节且不编造流程。另问文档外问题必须明确未覆盖。记录实际供应商/model、文档SHA、耗时、脱敏结果和退出码；只用公开使用手册与虚构问题，不发送真实课堂数据。

前端E2E：真实注册/登录→打开指南→提问→点击合法章节→关闭回到画布；API关闭时全文仍可读，画框/保存不受影响。没有向量化服务/依赖/新增检索基础设施；无模型调用时不标记真实问答成功。
